# 枝记 实时同步中转（Cloudflare）

让两台设备打开同一篇笔记时，对方一保存、你一两秒就看到（普通网盘同步要等十几到几十秒）。**网盘照旧兜底**，中转断了只是退回网盘，绝不丢东西。

## 普通用户：什么都不用装、不用部署

直接在枝记 **设置 → 同步 → 实时同步** 选「内置」即可，自动连上、马上能用。

下面的部署，**只有"想自己架一个中转服务器"的人**（比如作者搭官方默认站，或讲究的用户想用自己的）才需要看。普通用户可以忽略。

---

## 方法一：网页一键部署（零基础，推荐，不用装任何东西）

全程在浏览器里点几下，**不用装 Node.js、不用敲命令**：

1. 点这个按钮：

   [![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/daloudalou/ZhiNote/tree/main/realtime-relay)

2. 浏览器里**登录（或免费注册）Cloudflare**。按钮会顺带请你**授权 GitHub**——这是一键部署的固定流程：Cloudflare 借此把这份服务器代码复制一份到你的 GitHub，再从那里部署，以后还能自动更新。照提示点同意即可，是常规且安全的。
3. 出现配置页时，各项保持默认，点底部的**「Create and deploy / 创建并部署」**。
4. 等一两分钟，部署完成会给你一个网址，形如 `https://zhinote-relay.你的子域.workers.dev`。
5. 用浏览器打开这个网址，看到一行 **`ZhiNote realtime relay OK`** 就说明成了。
6. 回枝记 **设置 → 同步 → 实时同步** 选「自建」，把这个网址粘进去 → 保存。（填 `https://…` 即可，程序会自动用安全连接。）

> **可跳过（仅国内自建者可能需要）**：免费的 `*.workers.dev` 网址在中国大陆常被网络拦截、打不开。若遇到，可给这个 Worker 绑一个你已有的域名（Cloudflare 控制台 → 该 Worker → **Settings → Domains & Routes → Add → Custom domain**），再在「自建」里改填该域名。没有自己的域名、或用着正常，就不用管这条。

## 方法二：命令行部署（懂的人可选）

需要先装 Node.js。在本文件夹下执行：

```bash
npm i -g wrangler        # 没装过才需要
wrangler login           # 浏览器里登录你的 Cloudflare 账号并授权
wrangler deploy          # 部署，完成后会打印形如 https://zhinote-relay.<子域>.workers.dev 的地址
```

之后同方法一的第 5、6 步。

## 工作原理与隐私（放心用）

- **零知识**：客户端用你的同步口令把内容**加密后**才发出，中转站只转发"看不懂的密文"，看不到笔记明文。
- **房间隔离**：房间号由"你的口令 + 笔记随机编号"哈希得出，别人算不出同一个房间，互不串门；就算撞房间，没你口令也解不开。
- **不留痕**：只在"房间有人"时临时存一份最新快照供后到的设备追进度，**房间空了立即删除**；真正存档永远在你的网盘。
- **省钱**：用 WebSocket 休眠，连接挂着不发消息时不计费；到免费上限当天，客户端自动退回网盘同步，第二天恢复，不会扣钱。

## 为什么实时要用 Durable Object（而代理不用）

跨域代理是"无状态转发"，普通 Worker 就够。实时中转要把同一房间的多台设备**连在一起互相转发**，需要一个"有状态、能挂住长连接"的协调点——这正是 Durable Object（免费版支持 SQLite 存储后端，本项目已按此配置）。
